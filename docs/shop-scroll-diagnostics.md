# 비밀상점 드래그 전후 캡처 진단

이슈 22의 마지막 캡처는 Android 알림/빠른 설정 패널이다. 기존 로그에는 시작 직전 및 각 드래그 전후 화면이 남지 않아 게임 화면 전환 시점을 구분할 수 없다. 이 변경은 원인 진단을 위한 기록 보완이며 MuMu 업데이트 관련 화면 전환 원인을 확정하거나 해결한 것은 아니다.

기존 `_capture_screenshot`으로 성공한 화면의 시각과 용도를 기록한다. 일반 드래그 및 상단 복귀 드래그 전에 마지막 성공 캡처 PNG를 보관하고, 드래그 후 첫 번째 성공한 기존 캡처를 결과 화면으로 보관한다. 추가 ADB 캡처·입력·대기를 수행하지 않는다. PNG는 기존 파일에서 읽고, 최근 2회 드래그의 최대 4장만 메모리에 유지한다. 드래그 시점마다 별도 파일을 쓰지 않으며 오류 보고서를 만들 때만 `scrolls/01_normal_before.png` 같은 이름으로 저장한다. `report.json`에 드래그 순서, 종류, 좌표, 입력 성공 여부, 각 캡처 시각과 용도 및 파일 경로를 기록한다.

전후 화면은 드래그 직전·직후에 새로 찍은 이미지가 아니라 가장 가까운 기존 관측이다. 특히 구매 버튼 대기나 버튼 탐색 등 다른 용도의 캡처가 사용될 수 있으므로 용도와 시각을 함께 확인해야 한다. 성공한 사전 캡처가 없으면 이전 실행의 파일을 재사용하지 않는다. 캡처 실패 또는 다음 캡처 전 종료 시 누락 사유를 남긴다. 추가 진단 이미지의 쓰기 실패는 기본 보고서와 원래 오류를 덮지 않는다. 유료/자연 갱신 실행 시작 시 이력을 초기화하며 정상 완료·사용자 중지의 보고서 생성 정책은 유지한다.

실제 성능 수치는 측정하지 않았다. 추가 ADB 호출이 없고 메모리 보관량이 제한되는 것은 검사로 확인한다. 게임 내 화면 전환과 MuMu 사용자 환경에서의 동작 확인은 별도로 필요하다.
