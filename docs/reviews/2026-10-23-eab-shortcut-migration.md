# EAB 주소 전환과 기존 바로가기 교체

## 변경 범위

저장소 이름 변경 후 다음 릴리즈부터 `pelierze/EAB`만 조회하도록 기본 주소와
다운로드 허용 주소를 변경했다. 릴리즈·원격 설정·JSON 스크립트 조회에서 이전
저장소 주소를 탐색하지 않는다. 새 주소 조회에 실패하면 기존처럼 캐시·내장
데이터를 사용한다. 릴리즈 조회 실패 시 추가 주소를 찾지 않는다.
사용자 설정·프리셋·로그 경로는 변경하지 않는다.

## 바로가기 전환 조건과 순서

1. 사용자가 기존 `SecretShopBot-E7.exe`를 호출했을 때만 전환을 시도한다.
2. 같은 설치 폴더의 EAB.exe를 시작하고 인자를 그대로 전달한다.
3. Windows STARTUPINFO의 `STARTF_TITLEISLINKNAME`으로 사용한 바로가기를 식별한다.
4. 바로가기의 대상이 이 설치 폴더의 기존 EXE인지 확인한다. 확인된 바로가기와
   같은 위치에 EAB 바로가기를 만들고 기존 인자를 보존한다.
5. 새 바로가기의 대상과 인자를 검증한 뒤, 기존 파일이 확인 시점과 같은 파일인지
   해시와 대상 경로를 다시 확인하고 사용한 바로가기 하나만 제거한다.

기존 EXE를 직접 실행했거나 Windows가 사용한 바로가기 정보를 전달하지 않으면
현재 사용자의 바탕화면에 새 바로가기를 만들며, 기존 바로가기는 찾아서 삭제하지 않는다.
같은 이름으로 다른 설치를 가리키는 바로가기가 있으면 덮어쓰지 않고 번호를 붙인다.
이미 같은 대상·인자·작업 폴더의 EAB 바로가기가 있으면 재사용한다.
새 바로가기 생성·검증에 실패하면 기존 바로가기를 유지한다. 전환 실패는
`%LOCALAPPDATA%/SecretShopBot-E7/logs/launcher.log`에 기록하며 EAB 실행을 막지 않는다.

EAB.exe 직접 실행, 수동 설치만 한 경우, 자동 업데이트에서 전환 프로그램을
실행한 경우에는 바로가기를 자동 생성하지 않는다. 자동 업데이트의
`--update-ready` 프로세스 감시와 복구 시 자식 종료 처리는 유지한다.
전환 프로그램은 배포 전환 기간 동안 포함하고, 추후 배포에서 제외한다.

실행 경로 판별의 근거:
[Windows STARTUPINFOW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow).
PowerShell에는 경로·인자를 JSON과 Base64 데이터로 전달하며 코드 문자열로 평가하지 않는다.

## 검증

관련 테스트는 Windows COM으로 만든 실제 .lnk 파일의 생성·교체·재사용·이름 충돌,
한글·공백·따옴표·대괄호가 있는 경로, 다른 바로가기 보존, 생성 실패 시 기존 파일
보존, 자동 업데이트 시 전환 생략, 업데이트 복구 시 자식 종료, 새 저장소만 조회와
다운로드 주소 검증을 확인한다.

PyInstaller 빌드 후 `build/verify_shortcut_shell.py`로 실제 Windows Shell을 통해
전환 프로그램 바로가기를 실행했다. 이때만 새 바로가기가 만들어지고 클릭한
기존 바로가기만 제거되며, 다른 기존 바로가기는 유지되고 새 바로가기로 대체 앱이
실행되는 것을 확인했다. 테스트는 작업 폴더의 임시 파일과 무해한 대체 앱을 사용한다.
실제 게임 자동화는 이번 검증 범위에 포함하지 않는다.

관련 테스트 95개와 PyInstaller 빌드가 통과했다. `main` 전환 후 핵심 테스트
82개를 다시 실행해 통과했고, 새 저장소의 실제 릴리즈 조회·다운로드 주소 검증·
원격 JSON 조회와 데이터 검증도 확인했다. 당시 작업 폴더에 있던 별도 기능 변경은
이번 커밋에 포함하지 않는다.

이번 작업은 소스 커밋·푸시까지이며 버전 번호 변경, 태그 생성, 릴리즈 게시는 하지 않는다.
