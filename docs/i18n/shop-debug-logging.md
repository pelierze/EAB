# 비밀상점 변경 효과 확인용 디버그 기록

## 켜는 방법과 저장 위치

봇을 시작하기 전에 **디버그 모드 (상세 로그)**를 켠다. 비밀상점의 일반 갱신과 자연 갱신에 적용하며, 실행 중에는 디버그 설정을 변경하지 않는다.

세션별 실행 폴더 아래에 저장한다. 기본 GUI 세션의 예:

```text
logs/session_1/shop_debug/
  events.jsonl
  events.jsonl.1 ... events.jsonl.3
  evidence/*.png
```

실행할 때 일반 로그에도 진단 파일 경로를 안내한다. JSONL은 한 줄에 하나의 JSON 이벤트를 기록하는 형식이다. 글로벌 로그 수준을 DEBUG로 바꾸지 않고 선택한 세션의 진단만 별도 파일에 남긴다.

디버그를 끄면 진단 객체·파일을 만들지 않고, 추가 타이머·집계·증거 이미지 복사/저장도 수행하지 않는다. 기존 일반 로그와 기존 오류 보고서·스크롤 화면 보관 정책은 유지한다.

## 기록 내용

모든 이벤트에 `run_id`, `cycle_id`, `purchase_id`와 순서를 넣어 실행·사이클·구매를 연결한다. 시간은 밀리초 단위이며, `run_start`에는 버전·인식 방식 ID·실행 환경 클래스·해상도·임계값·대기 설정·실행 인자를 기록한다.

| 이벤트 | 용도 |
|---|---|
| `cycle_start`, `cycle_end` | 사이클별 전체 시간, 일시정지를 제외한 시간, 구매/건너뛰기/캡처/재확인/OCR 횟수와 시간 |
| `purchase_start`, `purchase_end` | 상품별 소요 시간, 확인 성공·이미 구매함·실패·중지·예외 구분 |
| `capture` | 기존 캡처의 용도와 성공 여부. 진단 때문에 새 캡처를 요청하지 않음 |
| `button_candidate`, `counter_scores`, `counter_read` | 버튼 위치·모양 점수, 수량 후보 점수·차이, 형태 판독 결과 |
| `item_anchor` | 상품 전체/내부 영역의 점수와 사용한 영역, 기대·확정 위치 |
| `verification_attempt`, `purchase_check` | 확인 횟수, 같은 상품 여부, 수량 변화·변경 픽셀 수, 위치 보정, 실패 사유 |
| `ocr_result` | 모호한 수량의 OCR 결과와 신뢰도. OCR 호출·최초 모델 로딩 횟수와 시간도 별도 집계 |
| `evidence` | 모호하거나 실패한 판정의 기존 상품·버튼 영역 이미지 경로 |
| `run_end`, `operation_error` | 실행 전체 집계·종료 상태, 처리 중 발생한 예외 종류 |

`metrics`의 주요 값:

- `captures`, `capture_failures`: 캡처 시도·실패 횟수.
- `purchases`, `skipped_items`: 이번에 확인된 구매 수와 시작부터 `0/1`이어서 건너뛴 수.
- `verification_attempts`, `verification_retries`: 구매 후 확인 횟수와 두 번째 이후 확인 횟수.
- `ocr_calls`, `ocr_loads`: OCR 호출 및 최초 모델 로딩 횟수. 사용하지 않은 경우 0.
- `capture_ms`, `recognition_ms`, `ocr_ms`, `ocr_load_ms`: 캡처·형태 인식·OCR 추론·모델 준비 시간.
- `input_ms`: 입력 호출에 걸린 시간. 입력 백엔드 내부의 지연도 포함한다.
- `wait_ms`, `pause_ms`, `natural_idle_ms`: 명시적 처리 대기·일시정지·자연 갱신 대기 시간.
- `verification_ms`: 구매 확인에서 다른 분류에 포함되지 않은 처리 시간.
- `diagnostic_ms`: 진단 기록·이미지 저장 시간. 디버그 자체의 비용을 구분하는 참고값.

중첩된 계측은 내부 작업 시간을 부모 분류에서 제외해 중복 합산하지 않는다. 전체 소요 시간에는 계측하지 않은 제어·일반 로그 처리 등도 포함되므로 분류별 시간의 합과 정확히 일치하지 않을 수 있다. 요약 이벤트의 집계는 그 이벤트를 쓰기 직전 기준이며 요약 기록 자체의 비용은 포함하지 않는다.

## 사이클을 비교하는 방법

- 일반 갱신: 두 페이지 스캔·구매·갱신까지를 한 사이클로 기록한다. 마지막 회차는 갱신을 하지 않으므로 `cycle_start.refresh_planned`가 false인 회차와 true인 회차를 분리한다.
- 자연 갱신: 두 페이지의 상품 확인까지만 사이클에 포함한다. 다음 확인까지의 약 15분 대기는 사이클 밖의 `natural_idle_ms`로 집계한다.
- `cycle_end.elapsed_ms`는 사이클의 경과 시간, `active_ms`는 이 중 일시정지를 제외한 시간이다. 게임 전환을 기다리는 시간은 실제 실행 비용이므로 유지한다.
- 구매 수가 0인 회차와 구매가 있는 회차, OCR·재확인이 발생한 회차를 나누어 비교한다. 실패·중지된 부분 사이클은 정상 완료 평균에 섞지 않는다.
- 같은 실행 환경·해상도·설정·디버그 활성 조건에서 비교한다. 진단 기록도 실행 비용이 있으므로 디버그를 켠 결과를 끈 결과와 그대로 비교하지 않는다.

PowerShell에서 현재 로그의 사이클 요약만 확인하는 예:

```powershell
Get-Content .\logs\session_1\shop_debug\events.jsonl |
  ForEach-Object { $_ | ConvertFrom-Json } |
  Where-Object event -eq 'cycle_end' |
  Select-Object run_id, cycle_id, mode, status, elapsed_ms, active_ms, metrics
```

로그는 현재 방식의 비용과 재확인·OCR 빈도를 보여준다. 기존 방식 대비 개선 폭은 동일한 계측을 적용한 비교 버전과 같은 조건에서 측정해야 한다. 높은 인식 점수나 수량 변화 로그만으로 실제 게임 결과가 항상 정확하다고 단정할 수 없으며, 의심되는 사례는 증거 영역과 게임 화면을 대조한다.

구매 후 내부 그림을 이용한 상품 재확인은 인식 방식 ID `shop_quantity_transition_v2`로 기록한다. `item_anchor`의 `full_score`, `inner_score`, `match_region`과 완료 기록의 `button_refinement`를 함께 확인한다. 이전 v1과의 차이는 [상품 재인식 보완](shop-item-reidentification.md)에 기록했다.

## 저장 한도와 오류 처리

- 이벤트 로그는 파일당 2MiB, 백업 3개로 세션당 최대 약 8MiB를 유지한다.
- 증거 이미지는 세션당 최근 20개 PNG만 보관한다. 이미지당 입력 메모리와 인코딩 결과를 각각 512KiB 이하로 제한한다. 오래된 증거는 삭제되므로 과거 로그의 이미지 경로가 더 이상 존재하지 않을 수 있다.
- 정상적으로 명확한 구매에서는 증거 이미지를 저장하지 않는다. 모호하거나 실패한 경우에도 이미 확보한 화면의 필요한 영역만 저장하며 별도 기기 캡처를 하지 않는다.
- 기록 파일을 생성할 수 없으면 일반 로그에 안내하고 진단 없이 실행한다. 실행 중 저장에 실패하면 경고 후 추가 기록을 중단하며 구매 판정·입력 동작·예외 전달을 바꾸지 않는다.

## 개발 검증

디버그 비활성 시 추가 타이머·기록 생성 없음, 활성 시 정상 구매 캡처 4회 유지 및 OCR·증거 저장 없음, 불확실한 경우만 추가 캡처와 증거 저장, 수량 점수·판정 사유·구매 식별자 연결을 재현 검사한다. OCR 로딩/호출 분리, 중첩 시간 중복 방지, 자연 갱신 대기의 사이클 제외, 실패·예외 시 부분 사이클 마무리, 세션 분리·용량 제한·저장 실패 시 동작 유지도 검사한다.

2026-10-23 기준 디버그 전용 검사 10개와 기존 상점·이미지·진단·GUI·배포 검사를 포함해 106개 검사가 통과했다. 디버그 활성·비활성의 동일 구매 재현에서 입력 좌표·순서와 캡처 횟수도 동일함을 확인했다.

실제 ADB·STOVE에서 로그를 수집하거나 사이클 속도를 측정한 상태는 아니다.
