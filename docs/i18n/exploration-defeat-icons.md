# 전투 패배의 언어 독립 판별

기존 2026-10-07 07:37:39 로그에는 패배 감지, 정산 이동, 초기 화면 복귀,
재도전 시작까지 기록되어 있다. 패배 후 처리 자체는 구현되어 있었지만
`defeat` 참조가 중앙 `FAILED` 글자 영역을 사용하고 있었다.

참조 화면 `battle_defeat_live.png`에서 문자보다 위에 있는 중앙 보라색
문양과 왼쪽 장식을 사용한다. 두 영역 모두 y=268보다 위에서 끝나므로
기존 결과 글자 영역(y=282~329)을 포함하지 않는다. 두 부분이 각각 유일하게
검출되고 상대 위치가 4픽셀 이내로 일치해야 패배로 인정한다. 전체 문양의
작은 이동은 제한된 탐색 영역 안에서 허용한다. 문자 참조로 돌아가는
폴백과 OCR은 사용하지 않는다. 중앙 문양이 없으면 장식 검사는 생략한다.

클릭은 기존의 안정 관측 및 클릭 직전 재확인 경로를 그대로 이용한다.
입력 위치는 새로 검출한 중앙 문양의 중심이다. 패배 기억을 우선하고,
정산을 닫아 초기 화면으로 돌아온 뒤 실패 횟수를 반영하며, 재도전 설정에
따라 다음 회차를 시작하는 흐름은 유지한다. 실패 진단에는 두 문양의
검출 결과를 추가하되 별도 상시 이미지 수집은 추가하지 않는다.

검증은 실제 기존 패배 참조, 글자 제거/무작위 픽셀 대체, 개별 문양 누락,
상대 위치 불일치, 전체 문양 이동과 다른 등록 화면 오인 여부를 검사한다.
문자를 지운 패배 화면에서 전투 종료 → 정산 닫기 → 초기 화면 복귀까지
재생하고, 기존 완주/미완주/패배/재도전 및 영문 정산 검사를 함께 수행한다.
합성 화면은 문자 영역 비의존성을 검증하며 별도의 실제 한국어 패배 캡처를
대신하지 않는다. 실제 게임 입력은 보내지 않는다. 게임에서 공통 패배
문양의 모양이나 위치 자체가 바뀌는 경우에는 추가 참조 검토가 필요하다.

검증 결과: 새 패배 판별 7개와 기존 완주/실패/반복 17개, 영문 정산 6개,
총 30개 검사를 통과했다. 이미지 감사표를 갱신하고 `compileall`과
`git diff --check`를 확인했다.
