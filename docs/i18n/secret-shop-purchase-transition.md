# 비밀상점 구매 전후 수량 비교

- 작업일: 2026-10-23
- 범위: 구입 버튼의 활성/비활성 판단과 구매 완료 확인
- 상태: 구현·재현 테스트 완료. 실제 게임 실행과 전체 사이클 시간 측정 전

## 변경 동작

고정된 채도나 저장된 버튼의 절대 색상과 비교해 구매 가능 여부를 결정하지 않는다. 구입 버튼의 모양을 흑백으로 찾고, 버튼 왼쪽 수량의 `1/1`과 `0/1`을 구분한다. 구매 완료는 **같은 상품의 구매 전 `1/1`에서 구매 후 `0/1`로 바뀐 경우**에만 인정한다.

1. 기존 구입 버튼 탐색용 캡처에서 상품 아이콘을 원래 위치 주변에서 다시 찾는다.
2. 그 상품 행의 오른쪽에서 중앙 문자 제외 마스크로 버튼 모양을 찾는다. 고정된 색상 차이 조건은 사용하지 않는다.
3. 수량이 `0/1`이면 이미 구매된 상품으로 건너뛴다. `1/1`이면 상품 아이콘, 버튼의 상대 위치와 수량 영역을 메모리에 기록한다.
4. 기존 두 단계 클릭으로 구매를 진행한다.
5. 기존 구매 확인 캡처에서 같은 상품 아이콘을 다시 찾는다. 작은 위치 이동은 아이콘을 기준으로 버튼 위치를 보정한다.
6. 같은 버튼의 수량이 `0/1`이고 구매 전 수량 영역과 실제로 달라졌는지 확인한다. 확인되면 통계를 한 번 증가시키고 종료한다.
7. 확인되지 않을 때만 설정된 최대 횟수 안에서 대기 후 다시 캡처한다. 완료 확인을 위해 구매 버튼을 다시 누르지 않는다.

수량은 작은 영역의 명암을 매 화면에 맞춰 이진화하고 숫자·슬래시의 모양을 비교한다. 이 방식으로 분명하게 읽히면 OCR을 생성하거나 호출하지 않는다. 수량이 모호한 경우에만 같은 캡처의 수량 영역에 OCR을 적용한다. OCR도 높은 신뢰도의 정확한 `1/1` 또는 `0/1`만 허용한다.

상품 아이콘이 없어졌거나 다른 상품이거나 화면이 가려져 확인이 불가능하면 성공으로 처리하지 않는다. 밝기·채도 변화만으로는 완료가 되지 않으며, 다른 상품의 비활성 버튼도 완료 근거로 사용하지 않는다. 캡처 실패 시 이전 파일을 읽지 않는다.

## 속도와 설정

- 정상 경로에 구매 전 캡처나 별도 안정화 캡처를 추가하지 않는다. 기존 구입 탐색 캡처와 구매 확인 캡처를 사용한다.
- 기존 `구매 완료 검증 횟수`는 `구매 완료 확인 최대 횟수`로 표시한다. 저장된 설정 키와 횟수 값은 유지하며, 과거 한국어 원격 라벨도 새 의미로 표시한다.
- 수량 변화가 분명하면 첫 구매 확인에서 종료한다. 설정이 3회인 정상 재현 사례에서는 구입 탐색 1회 + 구매 버튼 대기 1회 + 클릭 전 확인 1회 + 구매 후 확인 1회로 총 4회 캡처했다. 이전의 고정 3회 확인 흐름은 같은 조건에서 총 6회였다. 페이지 스캔 캡처는 이 수치에서 제외한다.
- 추가 검사는 완료 상태가 확인되지 않은 경우에만 수행한다. 계속 실패하면 기존 상위 실행 흐름대로 중지하며 구매 수량 통계를 증가시키지 않는다.

로컬 합성 화면에서 준비된 프레임을 20회 반복해 측정한 관측 처리 시간은 버튼 탐색 중앙값 약 28.78ms, 구매 완료 비교 중앙값 약 1.46ms였다. 측정 중 OCR은 로드되지 않았다. 파일 읽기·화면 캡처·ADB·STOVE 입력·게임 반응·기존 대기 시간은 포함하지 않은 CPU 처리 측정이며, 실제 1사이클 시간이나 개선 폭을 뜻하지 않는다.

## 구현 위치

- `src/shop_purchase_observer.py`: 수량 형태 판독, 조건부 OCR, 같은 상품 재탐색, 전후 비교.
- `src/secret_shop_bot.py`: 기존 캡처와 연결, 성공 시 조기 종료, 완료 후 통계 반영.
- `src/image_matcher.py`: 절대 색상 조건 없이 흑백 모양만 비교하는 선택적 경로. 다른 버튼의 기본 매칭 방식은 유지.
- `src/gui.py`, `remote_script.json`: 최대 확인 횟수 라벨. 구입 버튼 이미지 테스트에는 실제 탐색과 같은 모양 점수를 표시하고, 수량·상품 확인이 별도임을 안내.

`purchase_candidate`와 `verification_disabled_button`이라는 과거 원격 임계값 필드는 이전 버전과의 데이터 호환성을 위해 유지하지만, 새 수량 판정에서는 사용하지 않는다. 구입 버튼의 모양 탐색에는 기존 사용자 설정 `purchase_button` 임계값을 사용한다.

## 검증

변경된 구입 관측 13개와 기존 이미지 마스크·캐시·진단·상점 흐름·스크롤 보고·JSON 매크로·배포 검사를 합친 70개 검사가 통과했다. 관측 모듈 최종 정리 후 해당 13개와 GUI 26개를 함께 재실행해 39개 검사도 통과했다. 중복을 제외하면 96개다.

- 채도 배율 0 / 0.25 / 1 / 2, 밝기 배율 0.4 / 1에서 수량 판독.
- 변경된 색상에서 최초 활성·비활성 버튼 구분, 이미 구매한 상품의 무입력 건너뛰기.
- 같은 상품의 `1/1 → 0/1`만 완료 처리하고 통계를 한 번 증가.
- 다른 행의 `0/1`, 단순 어두워짐, 같은 수량 유지, 다른 상품·사라진 상품·가려진 화면의 성공 오판 방지.
- 작은 행 이동에 대한 상품 아이콘 기준 위치 보정.
- 모호한 수량만 OCR 호출, 부정확한 문자열·낮은 신뢰도 거부, 전후 변화 없이 OCR 결과만으로 성공 처리하지 않음.
- 정상 구매 첫 확인에서 조기 종료, 불확실한 경우에만 추가 캡처, 반복 구매 입력 없음.
- 캡처 실패 시 과거 성공 화면 재사용 방지와 중지 요청 처리.

위 검증은 저장소의 실제 아이콘·버튼 자산을 합성 화면에 배치하고 색상·위치·상태를 변형한 재현이다. 실제 게임의 애니메이션, 영어 수량 배치, 게임 패치로 바뀐 글꼴·버튼 크기, ADB/STOVE 실행은 추가 검증이 필요하다. 현재 수량 영역은 기존 183×53 버튼의 배치를 기준으로 하며, 버튼 배치가 달라지면 영역 정의도 재검토해야 한다.
