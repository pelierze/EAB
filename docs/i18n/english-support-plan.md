- 10월 24일의 UI 보완 커밋과 펭귄 작업을 `codex/i18n-penguin`에 함께 모았다.

- 탐사 우선순위의 표시 문자열·내부 값 분리는 탐사의 영어 지원 단계에서 진행한다.

후속 작업: [비밀상점 버튼 문자 제외 마스크](secret-shop-button-masks.md). 비밀상점 버튼의 중앙 문자 제외 마스크와 공통 매칭 경로를 구현했다. 전체 이미지 감사와 실제 영어 화면 검증은 남아 있다.

구입 상태 판정 후속 작업: [비밀상점 구매 전후 수량 비교](secret-shop-purchase-transition.md). 기존 캡처에서 같은 상품의 수량 변화를 확인하고, 명확하면 첫 확인에서 완료하며 모호한 경우만 재확인·OCR을 수행한다.

## 1. 목표와 범위

한국어 지원을 유지하면서 영어 사용자가 봇을 설정하고 실행하며, 영어로 설정된 게임 화면에서도 현재 제공하는 기능을 사용할 수 있도록 한다.

영어 지원은 다음 두 축으로 나누어 진행한다. 봇 UI를 번역한 것만으로 영어 게임 화면을 지원한다고 판단하지 않는다.

| 구분 | 목표 |
|---|---|
| 봇 표시 언어 | UI, 상태·통계, 사용자 로그, 오류·알림, 업데이트 안내를 한국어/영어로 제공 |
| 게임 화면 언어 | 한국어/영어 게임에서 비밀상점, 펭귄 구매, 자동 탐사의 인식·입력·완료 확인 지원 |

- 봇 표시 언어와 게임 화면 언어는 독립적으로 선택한다. 예: 영어 봇 UI + 한국어 게임.
- ADB와 STOVE에서 각각 검증한다. 게임 언어, 서버, Windows 언어, 연결 환경을 같은 설정으로 취급하지 않는다.
- 현재 이벤트 탭의 미지원 안내도 번역한다. `old/`의 중단된 기능은 이번 구현 범위에서 제외하되, 현재 실행 경로에서 참조되는지 확인한다.
- 이번 변경은 계획문서 추가까지다. 번역 코드, 이미지 교체, OCR 변경 및 릴리즈는 후속 단계에서 수행한다.

### 2.2 이미지에 한글이 포함되는가?

**포함된다.** 아래는 저장소의 대표 이미지와 JSON의 실제 `crop` 영역을 열어 확인한 결과다. 전체 자산의 분류가 끝났다는 의미는 아니며, 공통화 가능성은 영어 화면 대조 전의 후보 판단이다.

| 기능 / 실제 자산 또는 마커 | 확인한 문자·형태 | 공통화 검토 방향 |
|---|---|---|
| 비밀상점 `images/buttons/buy_button*.png`, `confirm_button*.png`, `refresh_button*.png` | 구매, 확인, 즉시 갱신 | 문자 제외 후 테두리·아이콘이 식별 근거로 충분한지 조사. 비슷한 버튼과 구분이 안 되면 언어별 템플릿 사용 |
| 비밀상점 `purchase_button*.png`, `purchase_button_disabled*.png` | 구입 + `1/1`, 비활성 구입 + `0/1` | 숫자·버튼 상태·상품 행 위치의 조합 검토. 문자 제거 후 활성/비활성 구분 유지 필요 |
| `images/items/` | 상품 아이콘. 우정 포인트에는 `50`도 포함 | 공통 후보. 영어판의 아이콘·수량 배치가 같은지 검증 |
| 펭귄 `images/penguin/buy_button.png`, `max_button.png` | 구매, 최대 | 일부는 문자 위주여서 단순 크롭으로 공통화하기 어려움. 주변 고정 앵커와 결합하거나 언어별 이미지 사용 |
| 펭귄 `egg.png`, `close.png`, `50check.png` | 알, 접기 모양, `50/50` | 공통 후보. 수량·완료 판정과 클릭 영역 유지 확인 |
| 영입 `recruit_card`, `recruit_active`, `completed` | 영웅 영입, 영입 완료 | 장식·상태 테두리·완료 아이콘으로 대체 가능한지 확인 |
| 영입 `filter_panel`, `filter_element_label` | 세트, 속성 | 실제 인식 영역이 글자 중심임. 필터 아이콘·패널 구조로 대체 가능한지 조사하거나 언어별 이미지 유지 |
| 노드 `enter`, `continue`, `story_confirm` | 탐사 입장, 탐사하기, 확인 | 글자 중심 영역이 있어 단순 문자 제거는 불가. 화면 상태 + 버튼 앵커를 함께 검토 |
| 노드 `shop_future_investment_title`, `hero_departure_title`, `expedition_summary` | 미래 투자, 이탈 영웅 선택, 별의 여정 | 제목만으로 화면·상품을 구분하는 경로를 조사. 고유 그림이나 복수 앵커가 없으면 언어별 자산 필요 |

중요한 구현 특성:

- `RecruitmentObserver`와 `NodeObserver`는 원본 이미지에서 JSON의 `crop` 영역을 잘라 템플릿으로 사용한다. 원본 전체에 한글이 있어도 인식 영역에는 없을 수 있고, 반대로 파일명이 영어여도 실제 영역은 한글일 수 있다.
- `RecruitmentObserver`는 영웅의 `completed_name` 마커도 로드한다. 초상화·선택 테두리·직업 완료 아이콘과 함께 현재 판정 경로를 추적해야 한다.
- 테마 선택은 모양 매칭과 색상 차이를 함께 사용한다. 이미지를 바꾸면 선택 전후 판정 기준도 재검증해야 한다.
- `ImageMatcher`는 컬러 이미지로 템플릿을 읽는다. PNG의 글자 부분을 투명하게 만드는 것만으로 인식에서 제외된다고 가정하지 않는다. 마스크가 필요하면 매칭 경로의 명시적 지원과 점수 기준 검증이 필요하다.

### 2.3 이미지 외 문자 의존성

- `src/chaos/node_observer.py`에는 `RANK UP` 텍스트 확인, 숫자 가격·잔액·카운터 OCR이 있다. 영문처럼 보이는 문구도 게임 언어별 실제 표기와 ROI를 확인한다.
- `assets/ocr/`에는 한국어 인식 모델이 있으며 README에는 과거 이벤트 텍스트 모드에 관한 설명이 있다. 현재 `exploration.py`는 이전 `ocr` 인자를 무작위 선택 정책으로 처리한다. 모델의 존재만으로 현재 한국어 OCR 의존성을 단정하지 말고 실제 호출·패키징 경로를 추적한다.
- 이벤트 선택지 본문을 번역하거나 새로 판독하는 기능은 이번 목표에 포함하지 않는다. 현재의 버튼 형태 기반 선택 정책을 유지하고 영어 화면에서도 금지·비활성 선택지 판정이 유지되는지 확인한다.

## 3. 우선 수행: 전체 이미지·인식 의존성 감사

영어 인식을 구현하기 전에 `docs/i18n/image-audit.md`를 작성한다.

1. 실행 중 로드되는 이미지를 코드, 두 layout JSON, 테마 감지기, 원격 매크로, 배포 수집 규칙에서 추적한다. 백업·대체 이미지와 조건부 복구 경로도 포함한다.
2. 원본 경로뿐 아니라 마커 ID, 실제 `crop`, 검색 `region`, 임계값, 상태 판정, 클릭 계산 및 다음 화면 확인까지 기록한다.
3. 실제 인식 영역을 시각적으로 확인해 다음으로 분류한다.
   - 문자 없는 아이콘·초상화·기호: 공통 후보.
   - 문자와 고유 장식이 함께 있는 영역: 문자 제외 크롭 또는 명시적 마스크 검토.
   - 문자만 있거나 동일한 버튼 외형: 대체 앵커 또는 언어별 템플릿 필요.
   - OCR·문자열 비교: 이미지 목록과 별도로 인식 언어 의존성 기록.
4. 한국어·영어의 같은 상태 화면을 확보해 같은 위치에 같은 고유 도형이 있는지 확인한다. 문구 길이에 따른 버튼 폭·정렬·줄바꿈·팝업 크기 변화도 비교한다.
5. 공통화 후보별로 기존 방식과 후보 방식의 탐지 결과를 비교한다. 정답이 없는 화면, 유사 버튼, 비활성·선택 전후·가림·전환 화면도 포함한다.
6. 각 항목을 `공통 유지`, `문자 제외 후 공통화`, `판정 방식 대체`, `ko/en 분리`, `추가 자료 필요` 중 하나로 결정한다. 근거 화면과 남은 제약을 함께 기록한다.

감사표 필수 열:

| 기능·상태 | 마커 ID·원본 경로 | crop·region | 한글/문자 포함 | 사용·복구 경로 | 공통화 후보 | KO/EN 근거 화면 | 오인식·클릭 영향 | 최종 결정·미확인 사항 |
|---|---|---|---|---|---|---|---|---|

공통화 원칙:

- 글자를 지우거나 배경색으로 덮은 이미지를 실제 게임 화면과 그대로 매칭하지 않는다. 문자 없는 고유 영역을 사용하거나 마스크를 올바르게 적용한다.
- 단색 버튼 조각만 남겨 서로 다른 행동을 같은 버튼으로 인식하지 않도록 한다. 화면 상태, 제한된 검색 영역, 복수 앵커 및 전환 확인을 조합한다.
- 템플릿을 작게 자르면 그 중심도 달라진다. 감지 사각형과 실제 클릭할 버튼 영역을 구분하고 기준점·오프셋을 다시 확인한다.
- 공통화가 불확실하면 정확한 언어별 템플릿을 사용한다. 영어 인식을 위해 전체 임계값을 일괄 하향하지 않는다.
- 재화 사용·구매·갱신·영웅 확정은 대상과 상태가 모호하면 입력을 진행하지 않는다.

## 4. i18n 설계안

### 4.1 번역 리소스와 내부 값 분리

- `src/i18n.py`와 `locales/ko.json`, `locales/en.json` 형태의 메시지 카탈로그를 제안한다. 파일 구조는 실제 로딩·배포 구조를 확인한 뒤 확정한다.
- `shop.start`, `connection.connected` 등 의미 기반 키를 사용하고 `{count}`, `{hero}`, `{version}` 같은 이름 있는 치환자를 사용한다. 문장 조각을 이어 붙여 번역하지 않는다.
- 한국어·영어 키와 치환자의 일치를 검사한다. 누락 시 기본 언어 문구로 대체하고 진단 로그에 누락 키를 남긴다.
- 직업·영웅·매크로 ID, 우선순위 숫자, 상태·종료 사유 코드는 언어와 무관하게 유지한다. 표시 문자열을 조건 분기나 저장 값으로 사용하지 않는다.
- 사용자용 로그·오류와 단계 표시는 번역한다. 진단용 코드·파일 경로·추적 정보는 안정적으로 유지하고 원본 예외 정보도 보존한다.
- 게임 내 영웅·아이템·기능의 영어 이름은 실제 영어 화면과 대조해 용어집으로 관리한다.

### 4.2 언어 설정

- `ui_language`와 `game_language`를 분리해 사용자 설정에 저장한다. 기존 사용자의 기본값은 한국어로 유지한다.
- 첫 버전은 봇 정지 상태에서 설정하고 재시작 후 반영하는 방식으로 단순화한다. 실행 도중 인식 언어를 바꾸지 않는다.
- 창 제목이나 Windows 언어만으로 게임 언어를 확정하지 않는다. 자동 감지는 후속 과제로 둔다.
- 여러 세션에서 사용하는 설정의 저장 범위와 기존 프리셋 호환성을 확인한다. 번역 때문에 영웅 구성·횟수·연결 설정이 초기화되지 않아야 한다.

### 4.3 인식 자산과 원격 데이터

- 검증된 언어 공통 자산을 먼저 사용하고, 필요한 마커만 명시적인 게임 언어에 맞춰 해석한다. UI 언어로 템플릿을 선택하지 않는다.
- 공통/언어별 자산의 경로·마커 정의와 해석 우선순위를 한 곳에서 관리한다. 필요한 영어 자산이 없을 때 한국어 문자 템플릿으로 조용히 대체하지 않는다.
- 원격 문구·매크로의 언어 키와 기존 JSON 호환 정책을 정한다. 언어 정보가 없는 원격 데이터가 사용자 선택 언어와 충돌하는 처리도 검증한다.
- 기존 리소스 루트·캐시·PyInstaller 수집 방식을 유지하면서 새 리소스를 포함한다. 저장소 실행과 배포 EXE에서 같은 자산을 찾을 수 있어야 한다.

## 6. 검증 계획과 완료 기준

### 6.1 자동 검증

- 번역 키·치환자·기본 언어 대체, 설정 저장·재시작 반영, 내부 ID와 기존 프리셋 호환성을 확인한다.
- 기존 기능별 테스트와 이미지 인식 테스트 중 변경 경로에 해당하는 검사를 실행한다.
- 실제 KO/EN 화면으로 정상 탐지와 오인식 사례를 검사한다. 같은 원본에서 잘라낸 템플릿을 같은 원본에 다시 매칭한 결과만으로 성공 판정하지 않는다.
- 공통화 전후 점수·위치·활성 상태 판정·화면 분류를 비교한다. 허용 임계값은 자산별 양성·음성 자료를 보고 정하고 문서화한다.
- 카탈로그, 공통/언어별 이미지, 실제 필요한 OCR 모델이 배포물에 포함되고 개발 폴더 없이도 로드되는지 확인한다.

### 6.2 실제 실행

| 축 | 확인 범위 |
|---|---|
| 언어 조합 | 한국어/영어 UI × 한국어/영어 게임의 네 조합 |
| 연결 환경 | ADB, STOVE 각각 연결·화면 정규화·인식·입력 |
| 비밀상점 | 상품 탐지·구매·비활성 구분·갱신·자연 갱신·중지·오류 보고 |
| 펭귄 | 알 선택·최대 수량·구매·완료 확인·반복·중지 |
| 자동 탐사 | 테마·필터·영웅/대체 영웅·영입 완료·각 노드·선택/금지 상태·재화 판정·정산·반복 |
| UI·업데이트 | 영어 문구 길이, 최소 창 크기, 탭·스크롤·로그 확장, 알림 및 updater, 설정 유지 |

완료 조건:

- 현재 활성 기능의 사용자용 문구가 한국어/영어로 제공되고 내부 분기가 번역 문구에 의존하지 않는다.
- 실행에 사용되는 이미지와 문자 판정의 언어 의존성이 감사표에 기록된다. 공통화 불가 항목은 언어별 처리로 해결한다.
- 영어·한국어 화면에서 인식·입력·전환·완료 판정이 확인되며, 모호한 구매/확정 화면에서 잘못된 입력이 발생하지 않는다.
- 실제 검증하지 못한 조합이나 화면이 있다면 지원 범위·제약으로 명시한다. 전체 지원 완료와 구분한다.
- 배포 EXE에서 언어 설정과 리소스 로딩이 동작하고 한국어 기존 설정을 이어서 사용할 수 있다.

## 7. 필요한 자료와 위험 요소

- 같은 게임 버전·해상도·가능하면 같은 상태의 KO/EN 캡처가 필요하다. 특히 구매 확인, 비활성 버튼, 영입 완료·대체, 필터 패널, 이탈·정산·오류/복구 팝업을 확보한다.
- 아직 영어 게임 화면과 실제 실행을 확인하지 않았다. 현재의 공통화 후보는 확정된 호환성 보장이 아니다.
- 문자 제거로 화면 고유성이 사라질 수 있다. 해당 경우에는 공통 이미지 사용을 고집하지 않고 언어별 템플릿과 상태 확인을 사용한다.
- 서버별 콘텐츠·UI 차이는 언어 차이와 분리해 기록한다. 영어 지원에 다른 서버의 모든 콘텐츠 지원을 자동으로 포함하지 않는다.
- 기존 미커밋 작업이 있는 상태에서 브랜치를 생성했다. 이번 문서 외의 변경은 이 계획 작업의 구현 결과로 취급하지 않는다.

테스트·인식 점수·실행 결과는 개발 검증 문서에 기록한다. `docs/releases/`와 GitHub Releases의 사용자용 본문에는 실제 변경, 사용법과 필요한 제약만 담고, 내부 검증 정보 및 체크섬 안내는 넣지 않는다.
